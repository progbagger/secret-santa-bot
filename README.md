# secret-santa-bot

Telegram-бот для проведения «Тайного Санты» в групповых чатах. Бот помогает собрать участников, провести жеребьёвку и напомнить о сроках, а личные сообщения использует для действий, которые нельзя показывать всей группе.

Проект пока находится на этапе начального каркаса.

## Что хочется реализовать

В групповом чате организатор сможет создать игру, настроить сроки и правила, открыть регистрацию и запустить жеребьёвку. Участники будут присоединяться через сообщение бота, а чат — видеть состав и общий статус игры без раскрытия пар.

В личных сообщениях с ботом участник сможет:

- посмотреть активные и завершённые игры, в которых он участвует;
- заполнить пожелания к подарку и при необходимости обновить их до установленного срока;
- после жеребьёвки узнать своего получателя и его пожелания;
- получать персональные напоминания и повторно открывать информацию о своей игре;
- анонимно уточнить детали подарка у получателя, если этот сценарий будет включён в правила игры.

Бот не должен публиковать результаты жеребьёвки в группе. Перед вступлением участник должен открыть личный чат с ботом: Telegram не позволяет боту первым написать пользователю. Жеребьёвка должна учитывать запрет назначать участника самому себе, поддерживать дополнительные исключения и заранее проверять, что при заданных правилах решение существует.

## Архитектура и технологии

Архитектура следует подходам `cringe-pics-telebot`:

- Python 3.14, aiogram 3 и полностью асинхронный I/O;
- тонкий Telegram-слой, бизнес-сценарии в `services/`, модели в `entities/`, доступ к данным в `repositories/`;
- PostgreSQL, SQLAlchemy и asyncpg как основное долговременное хранилище;
- Alembic для миграций;
- Redis для короткоживущих блокировок, дедупликации и координации фоновых задач, но не для хранения состояния игр;
- `uv` для зависимостей и запуска команд;
- Ruff, mypy, pytest и pre-commit для локальных проверок и CI.

Жеребьёвка и изменение её состояния должны выполняться атомарно в PostgreSQL. Сетевые обращения к Telegram не должны удерживать транзакции базы данных. Функциональные сценарии планируется проверять через настоящее приложение, PostgreSQL и Redis в Docker Compose и fake Telegram API с наблюдаемым состоянием, без произвольных задержек.

## Локальная разработка

Установить все группы зависимостей:

```bash
uv sync --locked --all-groups
```

Установить Git hooks:

```bash
uv run pre-commit install --hook-type pre-commit --hook-type post-merge
```

Запустить базовые проверки:

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy .
```
